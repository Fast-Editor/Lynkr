## 1. TOP STEALS (do these)

**S1. Blast-radius methodology → `~/ITSMBench/agents_lynkr/lynkr_pi.py` `_PLAYBOOK` (rule 10).** Closes the worst known weakness (ep-task family, 1/22). Compose from three quotable sources:
- Evidence ladder (skills/blast-radius): "1. You said so. Worthless on its own. 2. You pointed at the line. A real `file:line`... 3. You showed the bad case can't happen... 4. You ran it. A script or test that calls the real code and fails loud if you're wrong. 5. You reproduced it in the running app."
- The one-fact doctrine: "Most changes that look risky are safe because of a single fact... Find that fact. If it holds, most risky cases are cleared at once. Spend your time here, not on a long list of maybes." Plus: "don't hand back the writeup. Find the one or two facts the whole thing depends on and prove them by running code."
- Enumeration checklist ("look where grep stops"): "the JSON an API returns, a DB column, a wire format, another language reading the same bytes, a feature flag, code three hops downstream" — merged with Benny's five axes: "smoke the blast radius around the changed behavior. Cover nearby states, inputs, permissions, platforms, and failure paths that the change could affect."
- Output contract: What it does / The one fact (state it, say which rung, show proof; "if you couldn't prove it, write unproven") / Risks (likelihood AND cost, `file:line`) / Cleared (separate!) / "a search that finds nothing is still an answer, and never make up a caller."
Effort: ~1 hour of prompt editing + one bench rerun. Why it wins: it converts "consider impact" into a checklist + proof standard, which is exactly what ep-task graders reward.

**S2. Playbook trigger phrasings → `data/difficulty-anchors.json`.** Ready-made, hand-tuned anchor exemplars per class. Trivial: "check on PR X", "is it green", "what's using my disk", "mock it up", "a single module, a narrow question such as 'how does function X work'". Substantive: "how does X work", "a reported defect to reproduce, root-cause, and fix with runtime evidence", "rename, extract, inline, dedupe, move". Heavyweight: "sustained, scientific improvement of one metric against a target", "a measured slowness to trace and improve against a baseline", "get it green", "stress test this code", "find blind spots". Frontier: "run this whole project", "own this migration until it lands", "multi-day, many stacked PRs, dozens to hundreds of subagents", "one-way doors and high blast radius", "i'm going to bed... i want everything merged by morning". Also lift the "Distinct from X" disambiguators into the TypeSafe judge criteria — e.g. "Work one agent could finish inside the session's budget routes there, not here, however program-shaped the phrasing sounds" is the over-classification guard the judge lacks. Effort: ~2 hours (add anchors, re-embed, verify routing on a sample). Why: densest source of user-voice difficulty signal in the repo; these phrasings were themselves tuned for trigger accuracy.

**S3. Evidence-labeling + verification doctrine → `_PLAYBOOK` and judge criteria.** Three drop-in lines: (a) "Every claim carries its evidence or its label in the same sentence. Measured, inferred, or guess... Never hand the human a check you could run." (b) "Check a box only when its evidence exists, a file, a log line, a screenshot, a test run, or a SHA" + "Tests alone are not sufficient verification." (c) "A compile, unit test, code review, or plausible diff is not after evidence." Effort: minutes. Why: (a) alone is arguably the highest-leverage single sentence for bench scoring — graders reward evidence-labeled answers.

**S4. Judge kit → TypeSafe LLM judge.** Assemble from interrogate/: six-lens rubric (Correctness incl. idempotency, Root-cause-vs-symptom, Structural, Verification "check the real thing, not a proxy", Complexity "three lines of duplication beat a premature abstraction", Security "trace the input path"); calibration layer from lead-judgment ("If a reviewer's findings are all nits and style preferences, the code is probably fine", hypothetical-vs-actual, ≤5 Act-On cap, mandatory Dismissed-with-rationale); verdict enum VERIFIED / NOT_VERIFIED / INCONCLUSIVE with "Inconclusive is not a pass. Don't hide a negative." Plus eval.md blinding: "one judge scores both sets in a single pass on one scale, blind to which set each came from... by sanitized label only, never by model name." Effort: ~half day (criteria text + typed output schema). Why: fixes judge over-flagging and family bias with pre-compressed, gradeable questions.

**S5. Force-pattern upgrades → routing config (proposal only — per standing rule, never touch TIER_* yourself).** Add regex families from bugbot-triage's fix list: `security|privacy|data loss|auth|billing|migration|idempoten|race|retention` → force REASONING (idempotency/migration/billing are likely missing today). Add from SKILL.md: `cross.cutting|gnarly concurrency|subtle algorithm|blast.radius|what could this break|tear (this|it) apart|adversarial review|architect this`. Note the counterintuitive rule: a "precisely specified sequence of steps to execute to the letter" also routes to the strongest model — Lynkr under-routes these. Effort: ~1 hour + user sign-off.

**S6. Subagent contract → ACP lane / Claude Code subagent dispatch.** The orchestrate 9-field brief (GOAL/SCOPE/CONTEXT/ACCEPTANCE/VERIFY/TIMEBOX/FORBIDDEN/REPORT/STANDING) with "Missing fields are a refuse-to-spawn condition" and "Never resume-chain a brief. Respawn fresh with consolidated scope." Pair with the verdict lattice (live-ui-verified > unit-test-verified > type-check-only > verifier-blocked > verifier-failed; "CI green is an input to a verdict, not a verdict") and retry-by-mode ("cap-hit or oom, respawn with smaller scope. Network-drop, retry as-is. Tool-error, retry on a different model. Unknown, retry once. Two retries, then abandon"). Effort: 1-2 days; the refuse-to-spawn validation alone is cheap and immediate. Why: maps failure modes onto Lynkr's existing azure fallback, which is currently undifferentiated.

**S7. Lynkr Cursor plugin skeleton.** Copy `.cursor-plugin/plugin.json` field-for-field (directory pointers `"skills": "./skills/"`, `"agents": "./agents/"`); a `/setup-lynkr` skill modeled on setup-pstack (probe dashboard API for available models, write an always-applied overrides-only rule, "Never write a real slug you have not confirmed is available", absent-line=default); agents as poteto-agent-style thin shims over one canonical doc so bench and interactive agents can't drift. Headless caveat proven by Benny: plugins resolve via committed `.cursor/settings.json` for fresh agents, but "Never use a plugin source or cache path" in automation prompts. Effort: ~1 day for skeleton + verify skill (Doctor = one read-only GET against :8081).

## 2. WORTH A LOOK LATER
- **Arena protocol**: fan-out across Lynkr's tiers, cross-family judge, "convergence → ship cheap; divergence → reframe" as a routing signal; "A second opinion is the same prompt against a different model. Agreement is high-signal."
- **Epistemics 5-tier confidence** (Direct/Supported/Inferred/Speculative/Unknown) + sycophancy trap ("The user's guess is a prompt for investigation, not a conclusion to validate") → diagnosis playbook + judge.
- **attack-the-premise**: "two fixes sharing one premise failed the same gate → write the premise down, take a census" — best stuck-loop breaker for bench agents.
- **hillclimb decision.tsv** (id, hypothesis, before, after, delta, verdict) + "target plus a floor on attempts" → the methodology for hillclimbing `_PLAYBOOK` variants themselves.
- **why/ coverage map**: one investigator per evidence category (Splunk/Grafana/ServiceNow/SOPs/git), "document the null, don't skip the search."
- **Babysit phrase→mode mapping** ("check on X" → SIMPLE; "get it green" → REASONING) + CI flake rule ("An identical second failure means it was never flake").
- **Benny trust protocol**: typed markers from a configured identity, coordinator-only writes, compensation-on-partial-failure; Benny's `budgets:` + fail-closed config schema.
- **Overnight doctrine**: "a duration is not a finish condition"; "no owner merges on its own verdict"; Benny's Confirmed/Insufficient/Inconclusive verify taxonomy.
- **Fake-test litmus**: "would it still pass if every imported function returned `undefined`" → judge criterion.

## 3. SKIP
- **make-bot-ui webhook/secret hygiene** — Lynkr already does this; only "probe with a harmless payload before declaring live" is worth a line (folded into S7).
- **Feature-map UI selector specifics / control-adapter seven capabilities** — Playwright/ARIA-selector machinery doesn't transfer to an HTTP proxy; keep only the four-H2 doc shape.
- **Cursor `/automate` handoff, `.mdc` rule mechanics, gt/Graphite stacking, worktree-cleanup playbook** — Cursor/GitHub-workflow-specific plumbing.
- **bro/unslop/teach/technical-writing style skills** — prose style, no routing or bench payload.
- **pstack's literal model slugs** (grok-4.7-xhigh-fast, claude-opus-5-5-max) — patterns yes, slugs no; TIER_* mappings are user-owned per standing rule.
